# Работа с репозиторием

Здесь разрабатывается один универсальный плагин `1c-ai-core` для Codex.
Корень репозитория является корнем плагина. Это код плагина на Python/Node.js,
а не конфигурация 1С; для обычных правок и локальных регрессий EDT не требуется.

## Где искать

- `scripts/`, `mcp/`, `hooks/`, `policy/`, `vanessa/`, `ui/` — runtime плагина.
- `skills/` — навыки; `schemas/` и `settings/` — контракты и настройки.
- `tools/`, `packaging/`, `.github/` — сборка и публикация.
- `tests/` — регрессии; `docs/` — инструкции, архитектура и история проверок.
- `README.md` — вход для пользователя; `docs/DEVELOPMENT.md` — работа разработчика.

## Границы изменений

Плагин должен оставаться независимым от конкретного проекта. В поставке есть
только `profiles/generic-1c/`. Профили CRM/Kafka и локальные экспорты удалены;
их проработка отложена до отдельной задачи. Не добавляйте реальные проектные пути,
endpoints, credentials и instance bindings в исходники и установочный пакет.

Перед оценкой полноты миграции или переносом поведения из исходных окружений
прочитайте `skills/catalog.yaml`, особенно `migration_decisions`,
и `skills/README.md`. Принятые решения задают ожидаемый объём работ.
Репозитории источников перечислены в `docs/SOURCES.md`.

`1c-docs-mcp` (HelpSearchServer) и `1c-ssl-mcp` исключены, включая optional
и fallback подключения. Их отсутствие не является дефектом миграции.
Проверяйте заменяющие маршруты и их фактическое покрытие отдельно.

## Проверки

Запускайте проверки, относящиеся к изменению. Команды выполняются из корня
с установленными `requirements.txt` в виртуальном окружении:

```sh
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/test-bsl-ls-proxy.mjs tests/test-settings-ui.mjs
node tests/test-vanessa-ui.mjs
```

После изменения упаковки соберите и проверьте пакет:

```sh
bash tools/build-plugin.sh
python tools/check-plugin.py .build/marketplace/plugins/1c-ai-core
```

При изменении путей или состава поставки обновляйте сборщик, CI, тесты и ссылки
документации. Исключайте локальное состояние и инструменты разработки из ZIP.
Локальные тесты не доказывают live-приёмку EDT, v8std или внешних runtime.
Разделяйте подтверждённый результат и ограничения проверки.

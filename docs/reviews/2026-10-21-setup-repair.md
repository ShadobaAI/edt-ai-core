# Настройки и установка через чат — 21 октября 2026

Проверены чаты [«Настроить 1C AI Core»](codex://threads/01a15fa0-851c-7092-bb04-2e4405dbb93f)
и [«Продолжи настройку 1C AI Core»](codex://threads/01a15fa4-cd38-7613-9ca2-7a3c683ed008),
установленный пакет 0.3.0, текущие исходники и локальный журнал Codex.
Проектные профили, endpoints и исходники в исправление не включались.

## Причины и исправления

| Наблюдение | Причина и исправление 0.3.1 |
| --- | --- |
| На карточке видны только навыки и сведения о плагине | `settings.open` не объявлял самостоятельный App entrypoint; журнал обнаружения показывал `viewCount=0`. Добавлен глобальный вход «Настройки 1C AI Core». Ресурс и UI handshake поддерживают fullscreen и inline. Native layout `openai/settings` сохранён; его отрисовка и наличие App entrypoint проверяются отдельно. Точную причину отсутствия именно native-раздела в UI по этим данным установить нельзя. |
| Выбранный в настройках каталог не виден EDT/v8std/индексу | MCP-сессии раздельны; при запуске из каталога плагина и пустых host roots каталог оставался пустым. Добавлен явный `projectRoot` в `core_runtime_status` с привязкой только своей сессии, защитой host/environment selection и уведомлением tools discovery. Изменение roots сбрасывает привязку. |
| Совет открыть новый чат не помог; затем рекомендован перезапуск | Старый `sessionGuidance` предлагал обновление чата для любой проблемы доступности. Теперь он указывает поддержанный способ передачи каталога, а навык запрещает повторные чаты, подменные relays и чтение исходников плагина ради обычной настройки. |
| Настройка превратилась в исследование реализации | В двух чатах было 41 shell-обращение; во втором также были поиски в вебе, повторное чтение предыдущего чата и повторный doctor. Добавлен `settings.inspect`: ошибки профиля/совместимости, effective значения, источники, обнаруженные имена/порт EDT, разрешение подготовки и следующие шаги в одном компактном ответе. |
| Установка требовала отдельных программ для проверки соединений | `settings.probe_connections` проверяет EDT/v8std без запуска служб, а доступный `list_projects` — точные пути/имена/open/ready. Неполное покрытие явно остаётся непроверенным. Результат не подменяет привязку MCP-инструментов самого чата. В форме добавлена кнопка проверки. |
| Повторные немедленные запросы состояния | `settings.operation.waitMs` позволяет ждать завершения до 10 секунд, сохраняя ID, область и исход операции. Повторный запуск для ожидания не нужен. |
| Внешнему нормативному корпусу не нужен каталог проекта | Для v8std исключено объявление roots; даже неожиданный запрос roots получает пустой список. Тест записывает исходящий протокол и проверяет отсутствие пути проекта. Привязка и выбор настроенного URL остаются локальными. |
| Несовместимый профиль провоцировал поиск схем и кода | Компактная проверка возвращает текущую версию ядра, заявленную совместимость и ошибку валидации. Сценарий `inspect → edit → preview → apply → inspect` проверен на несовместимом профиле без чтения реализации. Согласование замены и backup сохранены. |

Контракт входа и fullscreen сверялся с
[официальной спецификацией OpenAI MCP Extensions](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#mcp-app-entrypoints)
и [рекомендациями по отображению](https://github.com/openai/mcp-extensions/blob/main/docs/patterns.md#display-modes).

## Расход контекста

- Основной навык: **13 116 → 5 623 UTF-8 байта, −57%**. Условно нужный
  runtime-контракт вынесен в reference и не загружается для обычной установки.
- На одном и том же синтетическом проекте полный `settings.read` занимал
  **7 602 байта**, новый `settings.inspect` — **1 715 байт (−77%)** полного
  сериализованного MCP-ответа. Пути временных каталогов влияют на точные размеры;
  регрессия проверяет устойчивое сокращение не менее чем на 25%.
- Статус и результаты операций сохраняют полную структуру, но не дублируют
  её вместе с инструкциями сервера в текстовом блоке.
- Это измерения входной инструкции и ответов, **не фактического списания
  лимита аккаунта**, токенов или качества нового живого прохождения установки.

## Проверки и ограничения

Итог: **233/233 Node-теста** без пропусков. Сборщик сформировал ZIP плагина
и marketplace 0.3.1; `check-plugin.mjs` подтвердил автономный запуск
распакованного пакета с Node-only PATH. `git diff --check` без замечаний.

Адресная live-проверка исправленных исходников подтвердила привязку EDT и v8std
через `projectRoot` в той же MCP-сессии при пустых host roots. EDT **2.21.1**
подтвердил оба точных пути: основной проект ready, тестовое расширение building.
v8std **1.27.0** подтвердил соединение после исключения передачи roots.
Сетевой отказ в песочнице не считался недоступностью самого сервиса; отдельная
проверка без ограничения сети прошла после устранения возможной передачи пути.
Исходники проекта, профиль и подключение установленного плагина не менялись.

Регрессии покрывают пустые/изменяющиеся roots, изоляцию сессий, запрет подмены
закреплённого каталога, ожидание первого ответа roots, gate подготовки managed
runtime, повреждённый/несовместимый профиль, native/App discovery, fullscreen,
кнопку проверки, точные и неверные пути EDT, bounded ожидание без перезапуска.
Упаковочный smoke дополнительно проверяет App entrypoint и compact inspection
из распакованного пакета с Node-only PATH.

Установка 0.3.1 в живой Codex, отображение нового входа и повторное сквозное
прохождение пользовательского проекта требуют отдельной проверки после обновления
установленного плагина. Пакет и протокольный smoke не доказывают такую приёмку.
Проверки не запускают ИБ, YaXUnit или Vanessa и не меняют 1С-исходники.

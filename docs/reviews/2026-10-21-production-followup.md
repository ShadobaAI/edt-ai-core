# Повторное ревью 1C AI Core 0.3.0

Дата: 21 октября 2026 года. Проверена итоговая рабочая копия поверх
`b3f4880bdafb05541f1997d40bd947bc3b4e9963`, с сохранением исходных пользовательских
изменений. Версия плагина, npm manifest и lockfile обновлена с 0.2.1 до 0.3.0.
Проверка опирается на код и исполняемые сценарии; прежние записи журнала являются
историей, а не доказательством текущего поведения.

**Результат:** подтверждённые дефекты R01–R10 первого ревью исправлены.
Повторное чтение выявило ещё одну ошибку внешнего code-index; она также исправлена.
В проверенном основном сценарии с EDT, v8std и code-index новых блокирующих
дефектов не обнаружено. Полная эксплуатационная приёмка всех необязательных
интеграций и установленного интерфейса Codex остаётся открытой; ограничения ниже.

## Что исправлено и перепроверено

| Первое ревью | Итоговая реализация и подтверждение |
| --- | --- |
| R01: неверный выбор проекта | Один resolver для settings, relay и hook. Сохранённый active_project не заменяет выбор чата; пустые roots снимают выбор, неоднозначные блокируют binding, неподдержанные используют каталог запуска. Каталог плагина исключён. |
| R02: коллизии состояния | Ключ строится по файловой идентичности после realpath, без лингвистического casefold. Проверяется владелец. Старый каталог сохраняется только при подтверждённом владельце; неизвестные подключения предлагаются для явного переноса. Unicode-коллизия воспроизведена и покрыта регрессией. |
| R03: небезопасное обновление | Проверенный кандидат хранится отдельно от active. Apply/rollback проверяют API, сохраняют предыдущий артефакт; code-index закрывает читателей перед переключением. Неподтверждённая остановка/рестарт сохраняют maintenance и outcome_unknown. Остановка проверяет собственный executable работающего daemon. |
| R04: отмена за выполняющимся вызовом | Control сообщения обрабатываются независимо; ID отображаются с учётом типа, отменённый в очереди вызов не отправляется. Пройдены stdio/HTTP cancellation и native callbacks. Timeout не разрешает retry writer. |
| R05: мёртвый процесс оставался готовым | Ошибка транспорта отклоняет pending requests, статус перестаёт быть готовым, следующее discovery восстанавливает соединение. Закрывается и ещё запускающийся клиент. |
| R06: потеря native contract | Для каждого binding доступны исходные instructions, capabilities, serverInfo и protocolVersion через core_runtime_status. | R07: лишние переподключения | Fingerprint учитывает только свой компонент, root/instance и зависимые mappings. Изменение соседнего подключения сохраняет рабочую сессию. Targeted reconnect покрыт регрессиями. |
| R08: неограниченный/невалидный ввод | Общий codec проверяет envelope, ID и UTF-8 размер stdio/JSON/SSE. Транспортный бюджет настраивается отдельно от размеров предметных ответов. Malformed child не оставляет процесс готовым. |
| R09: диапазон версии был фиктивным | Совместимость сверяется с фактической версией core по числовым компараторам; версия формата отделена. Несовместимый, но читаемый профиль можно исправить в редакторе с обязательными preview/revision/backup. |
| R10: скрытая первоначальная подготовка | Read/create/load/import профиля не готовят runtime. Начальная подготовка сохраняет разрешение для root/instance; последующие штатные старты используют его. Отключённые компоненты пропускаются. |

В повторном проходе `smoke` внешнего code-index вызывал stdio-only метод `call`
у HTTP-клиента. Теперь используется общий `request("tools/call")`, а `isError`
не считается успешным health. Новая регрессия проверяет готовность точного mapping,
отказ health и отсутствие установки managed runtime в external-режиме.

## Изменения подхода

- Общий доверенный реестр компонентов используется в подготовке, проверках и relay.
  BSL LS отключён по умолчанию; managed-компоненты включаются независимо для
  root/instance и поддерживают auto/external. Импортируемый профиль не исполняет
  произвольные команды провайдеров. Новый тип провайдера пока требует изменения
  исходников и соответствующих схем/упаковки; произвольного SDK расширений нет.
- В форме и чате используется один workflow обновлений: check → download → apply,
  при необходимости rollback. Скачивание кандидата сохраняет active. По умолчанию
  выбирается latest stable; точный upstream tag остаётся экспертной настройкой.
  Проверка Java определяется запуском и требованиями JAR, Vanessa — фактическим
  контрактом ответа, возможности MCP — живыми schemas. Версия служит provenance.
  npm lockfile и digest установленных артефактов сохраняют воспроизводимость и
  контроль целостности; это не запрет пользователю обновлять компонент.
- Подключения поддерживают env-ссылки на credentials, timeout и транспортный бюджет.
  Секретные значения не записываются в профиль/экспорт. Конфигурация проверяется
  общей схемой, расширенный редактор использует preview и контроль ревизии.
- Нормативный workflow получил assess_1c_requirements и validate_compliance_ref:
  нормализация/selection объединены, повторные detection/selection передаются
  ссылками текущей сессии. Сохраняются полный checker, явные target/sourceRef/phase,
  проверки дополнительных норм и возможность полного API. Проверка согласованности
  не выдаётся за анализ source или доказательство истинности evidence.
- Краткий requirements entry ссылается на подробный протокол по необходимости.
  Сохранены идеи старых CRM/Kafka harness: primary authority, bounded discovery,
  reuse, точный alias и guarded mutation. Проектные bundles и исключённые Help/SSL
  не возвращались; решения migration_decisions сохранены.

## Оставшиеся ограничения и рекомендации

1. **BSL LS:** нужен артефакт/внешний сервер с принятым native multi-workspace API.
   При включении несовместимого JAR пользователь получает ошибку; основной путь
   через EDT не зависит от отключённого BSL. Fallback через roots не добавлен:
   он противоречит принятому migration_decisions.bsl-native-multi-workspace.
2. **Существующий профиль CRM2:** указывает старый диапазон core `>=0.1.0 <0.2.0`.
   Итоговый core обоснованно отвергает такой профиль. Для live-проб использован
   проверенный кандидат с изменённым диапазоном только в памяти; исходный профиль
   не переписан. Полный новый lazy workflow на исходном профиле требует его
   осознанной миграции через редактор, а не скрытого обхода совместимости.
3. **Полная приёмка:** интерфейс установленного Codex, реальное обновление/откат
   upstream бинарников, multi-OS, YaXUnit/Vanessa execution и запись через EDT
   в этой сессии не выполнялись. Обновление/rollback и unknown outcome проверены
   исполняемыми fixtures. Не заявляется полная паритетность всех старых harness;
   OpenViking и дальнейшее покрытие замен Help/SSL остаются отдельной работой.
4. **Эффективность:** следующий полезный шаг — одинаковые реальные задачи на одной
   модели со старым harness и новым core, с измерением usage, времени и качества.
   Текущие изменения устраняют конкретные повторные передачи и переподключения;
   обещать процент экономии лимитов модели по synthetic payloads нельзя.

Архив подготовлен для проверки и установки; публикация, Git tag/commit и изменение
установленного пользовательского plugin cache не выполнялись.

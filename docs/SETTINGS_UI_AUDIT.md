# Интерактивные элементы настроек

Перечень относится к `ui/settings.html`. Имена в таблице — ID элементов;
динамические элементы указаны отдельно. `tests/test-settings-ui.mjs` в
большинстве сценариев моделирует обмен с MCP;
сквозные сценарии связывают код формы и реальный MCP-процесс через
тестовую DOM-среду. `tests/test-settings-scopes.mjs` также обращается к
реальному MCP-процессу. Для предсказуемых путей в тесте выбора файла ответ
диалога подставляется отдельно; эти проверки не доказывают работу окон ОС.

При открытии блока область записи выбирается по источникам его настроек:
локальный YAML имеет приоритет над общим профилем Git; для Java без проектного
переопределения выбирается «Все проекты». Подключения разных серверов, включение
каждого компонента и Java учитываются отдельно. Редактор конфигурации учитывает
весь локальный документ, а окна YaXUnit/Vanessa — только настройки своей интеграции
и общие команды тестирования. Ручной выбор и несохранённый черновик сохраняются
при фоновом обновлении; другой проект или экземпляр получает собственный выбор.
В справке каждая область описана отдельной строкой; «Все проекты» объясняется
только рядом с переключателем Java, где доступна эта область.
Очистка текстового или числового поля и нажатие «Сохранить» удаляют сохранённое
значение выбранной области, в том числе перекрытое другим слоем; действующее
значение заново вычисляется из остальных источников. Явно введённое действующее
значение можно записать в выбранную область. В локальной области общий параметр
после удаления показывается серым, а в общем профиле — обычным текстом.
Изменения и удаления нескольких полей сохраняются одной операцией с проверкой
ревизии; очистка ещё не сохранённого унаследованного поля просто отменяет ввод.
Сообщение о сохранении перечисляет область, компоненты и записанные поля;
удалённые переопределения указаны отдельно, ниже остаётся путь к файлу.

Сборка открытого EDT-проекта показывается как «Идёт сборка», а не как отсутствие
подтверждения подключения. Проверка Code Index сохраняет срок 15 минут;
наличие процесса индекса не подтверждает свежесть данных. Для уже работающего
демона обновление проверяет API через клиент только для чтения,
если подготовка разрешена для текущего проекта и экземпляра. Проверяются
пути, псевдонимы, состояние индексации и актуальность данных; сохранённый
результат заменяется свежим. При действующем разрешении проверка запускает
остановленный демон из установленного runtime.
Результат локального BSL LS сохраняется до изменения его окружения или настроек
запуска, с исходным временем проверки. Общий срок setup и изменения других
компонентов его не сбрасывают. При недействительном подтверждении или ошибке
фоновое обновление показывает соответствующее состояние без запуска JVM.
Адресная проверка API при действующем разрешении подготовки проекта и экземпляра
может запустить временную JVM и завершает её до возврата результата, включая
ошибки и таймауты. Успешный результат без изменений повторного запуска не требует.
Для внешнего BSL LS подтверждение действует 15 минут.
«Открыть папку» выделяет диагностический файл, находит окно именно его папки
и проверяет перевод Проводника на передний план; отказ Windows не выдаётся за успех.

При загрузке профиля выбранного проекта форма запускает фоновое обновление
компонентов, а затем повторяет его, пока форма видима. В режиме просмотра
другого проекта новые пробы не запускаются. Кнопка в шапке обновляет состояние
по сохранённым настройкам; открытие карточки отдельной проверки не запускает.
Фоновое обновление не запускает установку или JVM и не выдаёт новое подтверждение
полной готовности окружения. Разрешённый установленный code-index может запуститься.

| Элементы | Событие и ожидаемый результат | Условия и проверки |
| --- | --- | --- |
| `diagnosticsRefreshButton`, `logSearch`, `logLevel`, `expandJournalButton`, `journalDialog`, `journalDialogClose`, записи журнала, `logPeriod`, `exportLogButton` | Обновляют, фильтруют и раскрывают журнал, отдельно сохраняют журнал за 1, 3 или 7 дней | На вкладке показаны все загруженные записи после фильтрации в блоке высотой 217 px (около пяти строк), с внутренней прокруткой; новые события появляются снизу. «Открыть полный журнал» открывает все загруженные записи в окне на высоту экрана с шириной до 1040 px и внутренней прокруткой. Поиск, уровень, раскрытые записи и фокус сохраняются между режимами и при обновлении. Поток читает `settings.diagnostics` раз в две секунды, только на видимой вкладке поддержки (до 200 последних записей в пределах лимита ответа); скрытие документа и закрытие формы останавливают таймер. Прокрутка вверх приостанавливает следование; кнопки `journalFollowButton` и `journalResumeButton` выключают его или возвращают к новым событиям. Закрытие кнопкой, Escape или по подложке возвращает журнал на вкладку и фокус на «Открыть полный журнал». Чтение доступно во время операции; журнал сохраняет диагностические подробности, включая пути и сообщения об ошибках; распознанные поля авторизации маскируются, URL сохраняются без изменений |
| `discardDraftButton`, `editorSwitchDialog`, раскрываемые `details` | Отменяют изменения текущего документа, предлагают сохранить, отменить или оставить черновик при смене документа и показывают подсказки | Сохранение проходит через preview и подтверждение; несвязанные черновики сохраняются. При внешней смене проекта запись блокируется до отмены черновиков; `beforeunload` запрашивает защиту от закрытия, если хост её поддерживает |

При чтении истории журнал сохраняет положение видимой записи, пока она остаётся
среди последних событий. Удаление старых записей из ограниченного ответа не
сдвигает просматриваемую запись; это действует на вкладке и в полном окне.

Все основные действия проходят общий контроль занятости; длительные операции
отслеживаются по ID без автоматического повтора. Тесты охватывают готовность,
успех, ошибку, отмену, блокировку, изменение профиля и запоздалые ответы.

Нативные COM-объекты создания окон проверяются на Windows без показа. Реальные
передний план, владелец, возврат фокуса и поведение окна Codex требуют отдельной
интерактивной проверки; автоматические тесты с подставленным выбором их не
подтверждают.

Шапка содержит проект, экземпляр, число EDT-проектов и репозиториев, ветку Git
и состояния семи компонентов; эта сводка видна на всех трёх вкладках.
Карточки компонентов используют три колонки для внешних MCP и по две для управляемых
сервисов и тестирования; до 1100 px остаётся не более двух колонок,
до 760 px — одна. Модальные окна шириной до 980 px также переходят от двух
панелей к одной. В Code Index обслуживание индекса отделено от диагностики,
в BSL LS Java находится внутри панели настроек. Запись авторизации OpenViking
раскрывается отдельно, поле ключа скрывает введённый текст.
Редактирование имени открывается непосредственно под строкой профиля;
добавление раскрывает ввод каталога в списке, удаление убирает запись истории без
удаления файлов. Единственный профиль автоматически выбирается только
в общем окне настроек при отсутствии выбранного каталога. Контекст чата
не определяется историей; просмотр другого проекта сохраняет блокировку.

В группах из двух компонентов карточки занимают всю доступную строку.
Подготовка — отдельное общее действие с описанными эффектами и проверкой
разрешений; адресная проверка компонента её не заменяет.

Поля конфигурации строятся из действующих схем backend. `configurationValues`
и `configurationSources` — дополнительные данные чтения в существующем
snapshot настроек: действующие сохранённые значения и источники по путям.
Вычисление слоёв, замена массивов и карт заголовков выполняются общим resolver.
Имена переменных заголовков отображаются, значения секретов из окружения в форму
не добавляются.

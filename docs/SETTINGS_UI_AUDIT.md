# Интерактивные элементы настроек

Перечень относится к `ui/settings.html`. Имена в таблице — ID элементов;
динамические элементы указаны отдельно. `tests/test-settings-ui.mjs` в
большинстве сценариев моделирует обмен с MCP;
сквозные сценарии связывают код формы и реальный MCP-процесс через
тестовую DOM-среду. `tests/test-settings-scopes.mjs` также обращается к
реальному MCP-процессу. Для предсказуемых путей в тесте выбора файла ответ
диалога подставляется отдельно; эти проверки не доказывают работу окон ОС.

Смена слоя и переход к другому подключению не переносят чужой черновик; закрытие и Escape возвращают фокус; незавершённый переход проекта сохраняет блокировку |

При открытии блока область записи выбирается по источникам его настроек:
локальный YAML имеет приоритет над общим профилем Git; для Java без проектного
переопределения выбирается «Все проекты». Подключения разных серверов, включение
каждого компонента и Java учитываются отдельно. Редактор конфигурации учитывает
весь локальный документ, а окна YaXUnit/Vanessa — только настройки своей интеграции
и общие команды тестирования. Ручной выбор и несохранённый черновик сохраняются
при фоновом обновлении; другой проект или экземпляр получает собственный выбор.
В справке каждая область описана отдельной строкой; «Все проекты» объясняется
только рядом с переключателем Java, где доступна эта область.
Очистка сохранённого текстового или числового поля и нажатие «Сохранить» удаляют
его переопределение только в выбранной области: действующее значение заново
вычисляется из остальных источников. В локальной области общий параметр вновь
показывается подсказкой, а после переключения на общий профиль — обычным текстом.
Изменения и удаления нескольких полей сохраняются одной операцией с проверкой
ревизии; очистка ещё не сохранённого унаследованного поля просто отменяет ввод.
Сообщение о сохранении перечисляет область, компоненты и записанные поля;
удалённые переопределения указаны отдельно, ниже остаётся путь к файлу.

Сборка открытого EDT-проекта показывается как «Идёт сборка», а не как отсутствие
подтверждения подключения. Для локальных Code Index и BSL LS фоновое обновление
не запускает новые процессы и не продлевает 15-минутное подтверждение API.
Истёкшее подтверждение сохраняет время и отображается как устаревшее, с действием
для повторной проверки; наличие процесса индекса не подтверждает свежесть данных.
«Открыть папку» выделяет диагностический файл, находит окно именно его папки
и проверяет перевод Проводника на передний план; отказ Windows не выдаётся за успех.

Открытие формы, выбор проекта и минутный таймер обновляют состояние через общие
пассивные пробы сохранённых настроек. Они не запускают подготовку, установку или
перезапуск сервисов и не выдают новое подтверждение полной готовности окружения.
| `diagnosticsRefreshButton`, `logSearch`, `logLevel`, `expandJournalButton`, `journalDialog`, `journalDialogClose`, записи журнала, `logPeriod`, `exportLogButton` | Обновляют, фильтруют и раскрывают журнал, отдельно сохраняют журнал за 1, 3 или 7 дней | На вкладке показаны первые пять записей после фильтрации; «Открыть полный журнал» открывает все загруженные записи в окне на высоту экрана с шириной до 1040 px и внутренней прокруткой. Поиск, уровень и раскрытые записи сохраняются между режимами. Закрытие кнопкой, Escape или по подложке возвращает журнал на вкладку и фокус на «Открыть полный журнал». Чтение доступно во время операции; содержимое выводится как текст, известные секреты маскируются; в выгрузке могут остаться пути и адреса |
| `discardDraftButton`, `editorSwitchDialog`, раскрываемые `details` | Отменяют изменения текущего документа, предлагают сохранить, отменить или оставить черновик при смене документа и показывают подсказки | Сохранение проходит через preview и подтверждение; несвязанные черновики сохраняются. При внешней смене проекта запись блокируется до отмены черновиков; `beforeunload` запрашивает защиту от закрытия, если хост её поддерживает |

Все основные действия проходят общий контроль занятости; длительные операции
отслеживаются по ID без автоматического повтора. Тесты охватывают готовность,
успех, ошибку, отмену, блокировку, изменение профиля и запоздалые ответы.

Нативные COM-объекты создания окон проверяются на Windows без показа. Реальные
передний план, владелец, возврат фокуса и поведение окна Codex требуют отдельной
интерактивной проверки; автоматические тесты с подставленным выбором их не
подтверждают.

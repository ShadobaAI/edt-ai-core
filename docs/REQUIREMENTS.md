# Требования и ограничения

## Окружение

| Компонент | Требование |
| --- | --- |
| Codex | Настольный клиент с локальным исполнителем, плагинами и доступом к папке проекта |
| Node.js | 22+; `node` доступен процессам MCP и hooks |
| Проект | Доступный локальный каталог, валидный профиль и mappings репозиториев |
| EDT-MCP | Запущен пользователем, назначен этому контуру, обслуживает нужные открытые проекты |
| v8std | Доступный MCP-сервер нормативных материалов; может быть общим read-only для нескольких проектов |
| Code-index | По умолчанию включён; auto-артефакты: Windows x64, Linux x64, macOS arm64 |
| BSL LS | По умолчанию отключён; при включении нужны совместимая с JAR Java и native multi-workspace API |
| Vanessa | Для запуска manager поддерживается Windows; внешние 1С/Vanessa и runtime profile предоставляет проект |
| Сеть | Нужна для Git-магазина, загрузки managed-релизов и доступных по сети MCP |

Для разработки самого плагина дополнительно нужны npm и Git.
Для установленного пакета `npm install`, Python, PowerShell, Bash и компилятор
не требуются. Bash нужен только для необязательной dev-обёртки
`tools/build-plugin.sh`. Java, платформа 1С и внешние MCP в ZIP не включаются.

Поддержка Node.js на платформе не гарантирует наличие code-index-артефакта.
На иной архитектуре auto-загрузка отклоняется; external mode требует отдельно
доступного совместимого сервера. Windows arm64-модуль Koffi в пакете сам по себе
не означает поддержку managed code-index на Windows arm64.

## Разделение источников

- EDT отвечает за live-модель назначенного проекта, изменения и платформенную справку.
- Code-index отвечает за поиск и структурные факты в проверенной области индекса.
- v8std и policy используются для норм и их применимости.
- BSL LS предоставляет диагностику и семантические операции своего живого API.
- OpenViking — знания о механизмах и опыте; MCP ИБ — служебные runtime-сведения.
  **Обе интеграции: планируется.** См. [INTEGRATIONS.md](INTEGRATIONS.md).

`1c-docs-mcp` (HelpSearchServer) и `1c-ssl-mcp` не входят в плагин, в том числе
как дополнительные или резервные провайдеры. Документация платформы идёт через
EDT, установленный контракт библиотек проверяется через code-index/EDT.
Это распределение не доказывает полного покрытия прежних источников справки.

## Данные и доступ

Пути переносимого профиля относительны его корню. Путь вне корня, `..`,
некорректный schema contract и неизвестные repository IDs отклоняются.
Реальные профили и личные подключения не добавляются в поставку ядра.
Секреты передаются через окружение; `headers_env` хранит имена переменных,
а не значения HTTP-заголовков.

Защищённые исходники обслуживаются назначенными EDT/code-index, без обхода
через общий filesystem/shell. Политика требует разрешения с точным scope
для cleanup, запуска, операций над ИБ и remote Git. Явное поручение пользователя
может уже содержать такое разрешение; повторное подтверждение того же scope
не требуется. Host approvals остаются отдельным механизмом.

У каждого независимо выбранного контура — своё назначенное подключение EDT.
Клиентские сессии не изолируют общий workspace сервера EDT. Один v8std может
обслуживать несколько проектов, но evidence норм относится к своей задаче,
редакции, target и ревизии.

## Что результат проверки не гарантирует

| Подтверждённый факт | Что требует отдельной проверки |
| --- | --- |
| YAML проходит schema validation | Пути, готовность сервера и достаточность содержимого профиля |
| MCP отвечает на initialize/tools/list | Применимость конкретной операции и корректность её результата |
| Setup имеет статус `ready` | Активация hooks хостом, безопасность будущей записи, прикладная приёмка |
| Индекс готов | Актуальность каждого вывода относительно незакоммиченных правок и полнота динамических связей |
| Есть подходящий BSL LS JAR | Успех анализа именно этой конфигурации и тестов 1С |
| Локальные регрессии проходят | Live-приёмка внешних EDT/v8std/YaXUnit/Vanessa и UI установленного Codex |

Timeout или неизвестный исход записи не дают права повторить её вслепую.
Сначала проверяется authoritative-состояние. Специализированный recovery
EDT model gate применяется только к подтверждённому отказу до мутации,
по [контракту восстановления](../skills/1c-code-change/references/edt-recovery.md).

Недоступность OpenViking не является обязательным gate текущей реализации.
Для целевого контура знаний правила остановки описаны
в [документации интеграции](INTEGRATIONS.md#openviking).

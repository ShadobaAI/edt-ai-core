# Настройка и использование

Плагин устанавливается из магазина `ShadobaAI/codex-plugins` по
[инструкции в README](../README.md#установка-из-github-магазина).
Требования к окружению перечислены [отдельно](REQUIREMENTS.md).

## Первый проект

1. Запустите EDT с нужными проектами и его MCP-сервер, отдельно запустите v8std.
   Рекомендуемый форк с базой знаний по Vanessa и YaXUnit и готовый Docker-образ
   перечислены в [разделе о v8std](../README.md#v8std).
   Используйте адреса, выданные вашими серверами. Каждый независимо обслуживаемый
   контур EDT должен иметь своё назначенное подключение.
2. Откройте папку проекта в Codex. В чате с плагином напишите:
   **«Помоги настроить 1C AI Core для этой папки»**.
3. Агент проверит профиль и контекст каталога. Если профиля нет,
   создаст `.ai/project.yaml` из `generic-1c`. Шаблон ещё не содержит
   репозиториев: заполните пути, aliases и точные имена проектов EDT.
4. Укажите URL EDT-MCP и v8std. Если адрес EDT обнаружен из workspace,
   проверьте, что это нужный сервер. Обнаружение не заменяет явно заданный адрес.
   Режим знаний по умолчанию отключён (`provider: none`). Для OpenViking
   выберите переходный режим с нужными коллекциями либо обязательный KORA.
   Укажите адрес и включите флажок «Использовать OpenViking»
   (`openvikingEnabled: true` при настройке через чат). Выключение флажка
   сохраняет адрес; обязательные требования выбранного режима остаются в силе.
   Подключается уже работающий внешний сервер: получите у команды точный
   MCP endpoint, ID/URI коллекций, имена переменных поисковой авторизации,
   подтверждения прав и публикации с manifest. Плагин не устанавливает сервер,
   не создаёт знания, не запускает их индексацию/публикацию и не угадывает URL.
   Неполные сведения сохраняют блокировку зависимых действий, а не отключают
   требования знаний. Настройки транспорта доступны в форме и через чат;
   контракт режима и коллекций — в редакторе профиля с preview/apply.
5. Индекс кода и BSL LS включены по умолчанию; для BSL LS нужна подходящая Java.
   Сохранённые настройки могут их отключать. Разрешите подготовку включённых
   компонентов для этой папки и экземпляра.
6. Выполните проверку готовности. Дождитесь завершения уже запущенной операции:
   повторное нажатие не является способом проверить прогресс.

Создание профиля добавляет отсутствующие `.ai/PROJECT.md`, `.ai/.gitignore`
и `AGENTS.md`; существующие инструкции сохраняются.
Попросите агента дополнить их подтверждёнными правилами команды по
[руководству для проекта](PROJECT_AGENTS.md#как-создать). Созданный шаблон
и успешная проверка окружения ещё не означают, что правила проекта заполнены.
Подробный пример профиля и CLI — в [PROFILES.md](PROFILES.md).

## Настройки диагностик BSL LS

Для общих правил нескольких конфигураций используйте **один** файл, например
`.bsl-language-server.json` в корне проекта. Попросите агента задать нужные
параметры и подключить этот файл ко всем workspace текущего проекта.
Копировать одинаковый JSON в каждую конфигурацию не требуется.

Явный путь задаётся в `mcp.managed.bsl-ls.configuration` настроек плагина.
Чтобы применить его только к этому проекту, добавьте к существующему
`.ai/project.local.yaml`, сохранив остальные поля:

```yaml
components:
  bsl-ls:
    configuration: .bsl-language-server.json
```

Путь считается от корня профиля. Плагин передаёт его глобальному и workspace
загрузчикам BSL LS. Изменение пути переподключает соответствующую MCP-сессию.
Отдельные workspace-конфиги нужны для разных правил; при сочетании с общим
файлом сначала проверяют приоритеты используемой версии сервера.
`configurationRoot` указывает расположение метаданных 1С и не заменяет этот путь.

После изменения агент проверяет применение настройки через API анализатора
в нужной рабочей области. Валидный JSON и общая готовность сервиса этого
не доказывают. Если API недоступен, это ограничение указывается в результате.

## Два входа в настройки

**Из чата:** попросите «Открой настройки проекта 1C AI Core».
Откроется форма выбранного проекта без переключателя на чужие профили.
Агент открывает форму только по явному запросу открыть или показать её.
Создание, изменение, импорт и экспорт настроек через чат, проверка кода, BSL LS
и диагностика подключения выполняются без автоматического открытия формы.

**Через карточку плагина или приложение «Настройки»:** доступна общая форма
с поиском и списком известных профилей. Это история открывавшихся профилей,
а не каталог всех проектов компьютера. Выбор в этой форме не переключает
другие чаты и их MCP-сессии.

При выборе доступной карточки её настройки загружаются, если нет черновика.
При удалении выбранной карточки или карточки в каталоге без рабочего профиля
форма может открыть другой доступный профиль. Для этого каталог чата не должен
быть закреплён, форма не должна быть в режиме просмотра и не должно быть ошибки
выбора. Черновик сохраняется и блокирует переход: после его сохранения или отмены
профиль можно выбрать вручную. Удаление карточки не удаляет файлы профиля.

Форма позволяет менять подключения, компоненты, профиль и JSON/YAML-документ
настроек, проверять готовность, импортировать и экспортировать параметры.
Обе формы используют один backend.

При открытии формы, выборе и повторной загрузке профиля сводка состояния
обновляется сразу и запускается новая проверка готовности подключений,
индекса и API BSL LS. Она использует установленные компоненты и ранее
выданное разрешение подготовки для выбранного каталога и экземпляра.
Остановленный индекс запускается автоматически. Скачивание компонентов
и первоначальное разрешение подготовки остаются за кнопкой «Проверить
готовность»; открытие профиля их не выполняет.

Затем форма каждые 8 секунд читает состояние локального индекса и результат
последней проверки, без повторного запуска проверки. При возвращении к
скрытой форме готовность проверяется заново. Незавершённая операция
продолжает отслеживаться, несохранённые изменения откладывают автоматическую
проверку, а просмотр чужого профиля её не запускает. Сводка и «Сервисы проекта»
показывают один результат для выбранного каталога и экземпляра. Для BSL LS
«API доступен» означает успешную последнюю проверку, время которой видно
в подробностях. Пока индексируется проект или занята подготовка runtime,
готовность перепроверяется с интервалом 8 секунд после завершения предыдущей
проверки. Если индекс на диске найден, но сервер ещё не сообщил актуальность
данных, выполняются до трёх повторных проверок. Ошибки, отсутствие или
устаревание индекса такие повторы не запускают.

Проверка выполняется в фоне: вкладки, ввод черновиков и выбор профиля остаются
доступны. Сохранение настроек, установка и другие изменения сервисов ждут
её завершения. Независимые проверки компонентов и внешних подключений
выполняются одновременно.

Для подключений выберите область рядом с кнопкой «Сохранить»: профиль проекта
(`.ai/project.yaml`, можно передать вместе с проектом), локальные настройки
(`.ai/project.local.yaml`, для всех экземпляров этой папки) или этот экземпляр
(в пользовательском состоянии, только для выбранных проекта и экземпляра).
Под выбором указаны назначение области и путь файла. Поле показывает значение
выбранной области; если оно в ней не задано, показывается действующее значение.
Подпись различает значение в поле, несохранённый черновик и действующий источник.
При смене области черновик остаётся в поле и сохраняется в новую выбранную область.
Более приоритетный слой может оставить действующее значение без изменений.
Переменные окружения и внешний файл подключений имеют высший приоритет и
редактируются в своём источнике. Различия областей и порядок применения можно
посмотреть по ссылке «Чем отличаются области?» в форме.
В переносимом профиле пустой URL EDT/v8std недопустим; для явного отключения
используйте локальный или instance override.

Включение компонентов сохраняется в локальных настройках проекта или настройках
экземпляра. Для Java BSL LS доступны эти две области и общие настройки для всех
проектов; выбор, файл записи и кнопка сохранения находятся рядом. В Windows можно выбрать каталог Java:
форма найдёт `bin/java.exe` или `java.exe`, запустит `-version` и покажет путь,
версию либо ошибку. Доступность Java сама по себе не подтверждает совместимость
конкретного JAR. Общая настройка может влиять на другие проекты, а локальные
переопределения — скрывать её. Изменения проверяются схемой и повторным чтением
файла; изменение после загрузки требует обновить форму перед сохранением.

Раздел «Перенос» объединяет импорт и экспорт. Профиль можно импортировать из
JSON/YAML или другого доступного профиля из истории; цель — выбранный каталог.
Без явного выбора не переносятся подключения профиля, команды тестов и поля
транспорта и запуска из общих настроек, перечисленные в [профилях](PROFILES.md).
Другие поля профиля, в том числе `testing.yaxunit_config.launch_configuration`,
переносятся и могут зависеть от окружения. Аргументы команд могут содержать
локальные пути или адреса.
О пропущенных командах сообщает preview. Локальные и instance overrides другого
профиля не копируются. Preview проверяет
схему, репозитории, containment и manifest знаний, показывает отсутствующие
относительные пути и сопоставляет имена EDT-проектов с местными `.project`.
Это не проверка подключения к EDT. Замена профиля требует подтверждения. При отсутствии
профиля создание и импорт доступны рядом; повреждённый профиль можно открыть
для исправления или заменить с подтверждением. Переименование меняет только
`project.id` и сохраняет резервную копию; разрешения Vanessa для прежнего ID
придётся получить заново.

В редакторе выберите область «Этот экземпляр», «Локальные настройки проекта»,
«Профиль проекта» или «Все проекты». Профиль и общие настройки среды показаны
как отдельные документы; изменение одного не перезаписывает другой. Это позволяет
редактировать дополнительные поля через форму; preview проверяет схему
выбранного документа. В дереве
строки вводятся без JSON-кавычек, тип можно сменить явно; текстовый режим
сохраняет синтаксис JSON/YAML. В Windows форма использует
нативные окна выбора папки, открытия файла и «Сохранить как», а уже известную
папку открывает в Проводнике. При отмене запись не выполняется; если активное
окно или нативный диалог недоступны, форма сообщает об ограничении. В остальных
средах импорт может использовать выбор файла браузера; экспорт настроек и
диагностики сохраняется в отдельные файлы каталога состояния плагина.

## Что проверяет готовность

| Проверка | Значение результата |
| --- | --- |
| Профиль | Валидность данных и наличие сопоставлений репозиториев |
| EDT | MCP-соединение, инструменты и совпадение точных имён/путей, открытости и готовности проектов, если сервер предоставляет нужные сведения |
| v8std | MCP-соединение и непустой список инструментов |
| Индекс кода | Подготовка runtime, подключение и готовность индекса по репозиториям |
| BSL LS | Проверка включённого runtime и необходимого native workspace API |
| Policy и навыки | Ответ bundled policy, наличие файлов навыков, hooks и конфигурации |

Статусы `not_checked`, `blocked`, `ready`, `stale` относятся к настройке окружения.
Результат сохраняется с временем проверки и устаревает через 15 минут либо при
изменении настроек и проверяемых файлов. Остановка локального индекса также
может сделать результат устаревшим. Проверка не подтверждает активацию hooks
хостом, успех будущей записи EDT или прохождение тестов 1С.

В чате агент использует `settings.inspect` для общей картины,
`settings.probe_connections` для внешних подключений и `settings.run_check`
для подготовки и проверки. Долгие операции возвращают ID; их результат
читается через `settings.operation`, без повторного запуска.
Эти вызовы и `settings.check` возвращают данные без открытия формы;
`settings.check` читает ту же сводку, что и `settings.inspect`.
Проверка подключений может использовать несохранённые поля транспорта EDT,
v8std и OpenViking. Она возвращает ID операции; `settings.operation` с этим ID
и `waitMs` до 10000 ожидает тот же результат без нового запуска. Черновик формы
и редактора сохраняется; такая проба не применяет настройки и не снимает
требования знаний. Для работы с новым адресом сначала сохраните его.
Настройка через чат не открывает форму автоматически. Оба входа формы,
чатовые инструменты и CLI используют `SettingsBackend` с одинаковыми
правилами выбора каталога, экземпляра, overrides и проверки ревизии.
CLI `node <PLUGIN_ROOT>/scripts/settings_backend.mjs` принимает JSON-запрос
через stdin: например, `{"action":"read"}` или
`{"action":"update","set":{"openvikingTimeout":10}}`.
Для вызова задаются `EDT_AI_PROJECT_ROOT`, `EDT_AI_INSTANCE`,
`EDT_AI_STATE_DIR`, `EDT_AI_SETTINGS`; результат — JSON с `ok` и `result`
либо ошибкой. Секреты в JSON не передаются.
`core_runtime_status` подключает нужный управляемый MCP в сессии чата
с ранее выданным разрешением для каталога и экземпляра. Первичная подготовка
по-прежнему требует разрешения. Каталог relay содержит управляющие инструменты;
агент получает живые схемы через `core_runtime_tools` и вызывает native API
через `core_runtime_call`.
Статус relay отдельно показывает `nativeCatalog` (доступен, пуст или не проверен)
и, при отказе подключения, этап и категорию ошибки. `ready` относится к соединению,
а не к доступности конкретной нормы или готовности workflow; проверка policy и
фактическое чтение нормы выполняются отдельно в нужной сессии.
При пустых host roots оба принимают каталог этого чата в `projectRoot`.
Регистрацию workspace BSL LS и анализ файлов можно выполнить одной короткой
последовательной группой, сохраняя их в одном процессе. Разрешения применяются
к каждой операции; ошибка останавливает группу без автоматического повтора.
В `actions` каждая операция имеет позицию с единицы и состояние: успешный ответ
(`response_ok`), ответ с ошибкой (`response_error`), неизвестный исход после попытки отправки
вызова (`unknown`), отсутствие запуска (`not_started`) или успешный ответ с
последующей остановкой workflow (`response_ok_workflow_stopped`). Подробности
содержатся в `results`; ответ с ошибкой не доказывает отсутствие побочных эффектов,
а подтверждение приёма не означает завершение асинхронного задания.

## Обновление компонентов

В разделе компонентов выберите версию и нажмите «Установить». Одна операция
скачает выбранный выпуск, проверит его API и переключит компонент. Чтобы
вернуться к старой версии, выберите её в том же списке и установите.
Сам выбор ещё не меняет настройки runtime: версия сохраняется для всех
проектов пользователя только после успешной установки. При ошибке загрузки
или проверки API сохраняются прежние рабочая версия и настройки.
Это обновление **code-index/BSL LS**, а не самого плагина и внешнего EDT/v8std.
Кнопка недоступна, если выбранный выпуск уже используется. Для `latest`
сравнивается стабильный выпуск GitHub, а не строка настройки или первый
предварительный релиз в каталоге. Пока `latest` не определён, можно обновить
список или выбрать конкретную версию. Для индекса учитывается работающий
сервис текущего проекта: если он остался на старой версии, переключение доступно.
При рассогласовании сохранённой и рабочей версий установка остаётся доступной
для восстановления настроек.

`latest` выбирает стабильные релизы. Предварительные версии включаются отдельно
для компонента; точный tag закрепляет конкретный релиз. Установка требует
разрешения подготовки в текущей области. Отдельные операции проверки,
скачивания, применения и отката сохранены в `settings.updates` для совместимости.
Если версия закреплена в локальных настройках проекта или экземпляра,
конфликтующий выбор отклоняется до скачивания; сначала измените локальную настройку.
Проверка API и переключение выполняются в текущем проекте. Уже запущенные
сервисы других проектов не перезапускаются автоматически; им может потребоваться
отдельный перезапуск для перехода на установленную версию.

Чтобы обновить каталог версий или повторить неудачную загрузку, нажмите значок
обновления рядом с поиском внутри списка. Он обходит кэш каталога и запрашивает
свежий ответ GitHub. Выбранная версия и текст поиска сохраняются. Пустой ответ
первой страницы перепроверяется альтернативным запросом и, при необходимости,
загрузкой всех страниц по 50 выпусков. Пустые промежуточные страницы, на которые
указывает пагинация GitHub, также перепроверяются. Пустой или неполный каталог
не сохраняется как успешный список; если получить выпуски не удалось, форма
показывает ошибку загрузки и сохраняет ранее загруженные строки.

Для обновления самого плагина обновите источник магазина и установленный
плагин средствами Codex. В CLI источник обновляется командой
`codex plugin marketplace upgrade shadobaai`; обновление источника само по себе
не подтверждает перезагрузку уже работающих MCP-процессов.
Исходники dev-checkout, установленный plugin cache и работающий MCP — разные
копии. Правка checkout или обновление магазина не обновляет автоматически две
остальные. Сверяйте `build-info.json` установленного пакета и `serverInfo` живого
MCP; перезапускайте свои соединения штатным способом. Профили `.ai/`, overrides
и пользовательский каталог состояния хранятся вне пакета и не заменяются при
его обновлении. Dev-команда `prepare_install` требует новый destination и
сохраняет пользовательские настройки; она не является обновлением plugin cache
или остановкой работающего MCP. Совместимость/откат описаны в [PROFILES.md](PROFILES.md).

## База знаний и информационная база

OpenViking предоставляет поиск по базе знаний БСП, проекта и проверенного опыта;
плагин поддерживает режимы знаний, workflow gates и клиентский адаптер.
Публикация, права сервера и live-приёмка проверяются отдельно. Отдельного MCP
информационной базы в плагине нет. Контракт текущей рабочей копии подтверждается
через EDT/code-index.
Назначение и границы доступа описаны в [INTEGRATIONS.md](INTEGRATIONS.md).
Doctor, setup-пробы и support report возвращают `verificationLimits`:
наличие конфигурации и файлов hooks не подтверждает их активацию хостом.
Граница чтения может быть подтверждена внешней подписью; плагин отдельно
обозначает непроверенные серверные запреты, обходы доступа и качество корпуса.
Диагностика конфигурации показывает только доступные декларации, включая
отключённые остаточные маршруты; эффективный каталог хоста остаётся непроверенным.
Текст ошибок внешнего MCP, stderr backend и содержимое логов runtime не включаются в диагностику;
сохраняются безопасные коды и категория. Ошибки разбора не цитируют входной
документ. Из журналов, результатов операций, readiness-кэша и support report
исключаются известные credentials и их обычные кодированные представления.
Readiness receipts версии 3 сохраняют служебные статусы без изменения и очищают
диагностический текст. Старые receipts требуют новой setup-проверки; их сообщения
не загружаются в ответы. При timeout/завершении stdio сохраняется неизвестный
исход операции, без добавления stderr в ошибку.
Журнал формата 2 не раскрывает содержимое записей прежних и неизвестных
форматов: сохраняются время и отметка об исключённых данных. Это также
распространяется на старые `request_failed` со строковыми ошибками и stack.

## Перенос настроек

Экспорт формы создаёт документ `1c-ai-core-settings` с переносимым профилем
и общими настройками runtime. Личные overrides экземпляров в него не входят.
В Windows папка и имя выбираются в системном окне «Сохранить как»; замена
существующего файла требует подтверждения в этом окне. В Linux и macOS файл
сохраняется в `exports/1c-ai-core-settings.json` каталога состояния; следующий
экспорт заменяет его. Форма показывает подтверждённый путь.

Импорт сначала показывает проверенный предпросмотр. Для замены существующего
профиля требуется явное подтверждение; перед записью создаётся резервная копия
`.ai/project.<timestamp>.<id>.bak.yaml`. Если настройки изменились после
предпросмотра, нужно сверить новый документ. В режиме редактирования передаётся
полный документ: пропущенные runtime-поля возвращаются к defaults.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Навык виден, MCP настроек отсутствует | Локальный исполнитель, Node.js в `PATH`, запуск `1c-ai-settings` |
| Не выбран каталог | Папку текущего чата; агент может передать её в `projectRoot` при пустых host roots |
| Найдено несколько профилей | Откройте конкретную папку проекта; выбор не заменяется последней записью истории |
| EDT подключён, но проект не готов | Точные имена и пути, открытость проекта, завершение сборки модели EDT |
| Индекс строится | Дождитесь текущей операции и проверьте её результат |
| BSL LS несовместим | Java и native multi-workspace API выбранного JAR |
| Изменение URL не действует | Источник effective-значения: environment, connections file, instance или repo-local override |

Пустые roots в одной MCP-сессии агент может дополнить известным каталогом
этого чата через `core_runtime_status({projectRoot})` нужного подключения.
Это не меняет host-owned выбор и не переключает другие сессии.

В разделе диагностики есть журнал и **«Сохранить диагностику»**. В Windows место
сохранения выбирается в системном окне; в Linux и macOS отчёт сохраняется в
`diagnostics/exports/1c-ai-core-diagnostics.json` каталога состояния и заменяется
следующим экспортом. Форма показывает путь; на Windows можно открыть папку.
Экспорт не отправляет файл
в чат или на сервер. Журнал ограничен четырьмя файлами по 512 КиБ и семью днями,
известные секреты скрываются. Каталог состояния по умолчанию —
`~/.codex/1c-ai-core` или `${CODEX_HOME}/1c-ai-core`.

# Контракт встроенных настроек

Native settings предоставляют `settings.read/update`, импорт/экспорт и MCP App.
Чат и ручная форма используют один backend: read/update, preview/apply,
edit, export_data и run_check доступны также модели. Навык edt-ai-core ведёт настройку
в чате по одному вопросу, с перечитыванием effective значений после записи.
В manifest указан onboardingSkill для входа в этот сценарий из setup плагина.
Также указан requires_local_executor: true: настройки обслуживаются локальным
stdio MCP. Перед настройкой навык проверяет доступность settings.read через
discovery host и отличает отсутствие инструментов от отсутствия выбора папки.
Если локальный MCP не подключён, навык диагностирует окружение/запуск сервера,
а не отправляет пользователя повторно создавать чаты без исправления причины.
Ручная форма включает редактор JSON/YAML профиля и общих параметров runtime.
`settings.edit` возвращает документ и baseRevision. Preview/apply в режиме edit
проверяют этот снимок и revision предпросмотра; изменение текста сбрасывает preview.
Удалённые runtime-параметры сбрасываются к defaults, секции сохраняются без слияния
со старыми overrides. Неизменённый профиль не записывается, сохраняя комментарии
и mtime; изменённый требует подтверждения замены и backup. Внешний импорт
сохраняет прежнюю семантику слияния. Подключения экземпляра остаются отдельными полями.

Вторая точка входа объявлена через `openai/settings`: нативный layout содержит
App-действие `settings.open` («Открыть настройки»), принимающее `{}` и открывающее
форму в модальном окне без чата. `server/discover` принимает современный discovery
probe, возвращает resultType=complete и фактически поддерживаемые legacy versions;
последующие вызовы используют initialize handshake. Stateless-вызовы инструментов
по неподдерживаемому протоколу отклоняются, изоляция сессий сохраняется.
Контракт сверён с [официальной спецификацией](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#structured-settings).
Видимость setup и отрисовка карточки в установленном Codex требуют отдельной
live-приёмки. Переключатели навыков Codex плагин не добавляет.
Пользователь выбирает файл, проверяет папку, реальные effective URL и изменения
общих параметров runtime. Замена существующего профиля требует подтверждения;
перед ней сохраняется backup. После импорта доступна отдельная подготовка MCP
с фактическим разрешением запуска для выбранного проекта и экземпляра.

## Интерфейс и работа из чата

MCP App открывается на вкладке «Профиль». «Импорт», «Экспорт» и «Сервисы»
разделяют перенос настроек и запуск runtime. Цвета используют переменные host,
тема учитывает host context и системную тему. Строки сервисов раскрывают
диагностику по нажатию. ResizeObserver сообщает высоту содержимого с задержкой
50 мс и подавлением субпиксельных колебаний. Фиксированная высота host не меняется;
для гибкой высоты учитывается `containerDimensions.maxHeight`. Место под полосу
прокрутки зарезервировано, чтобы её появление не меняло перенос строк и высоту.
Длинные подробности доступны через прокрутку. Уведомление с результатом входного
инструмента выбирает вкладку один раз; повторные уведомления host и ответы
на вызовы из приложения не переключают экран и не перезапускают polling.

`settings.profile` доступен модели и приложению и возвращает `profile.status`:
`unselected`, `missing`, `ambiguous`, `invalid` или `loaded`, путь, ID и репозитории. `loaded`
означает разбор и проверку схемы, не готовность runtime. Ошибка YAML/схемы не
блокирует экран импорта рабочей копии. `settings.create` создаёт только отсутствующий
generic-профиль и недостающие инструкции; Git-подкаталог нормализуется к корню.
`settings.load` валидирует существующий профиль и записывает scoped reconnect
token. Эти действия не меняют defaults других проектов и не запускают bootstrap.

`settings.profile/read.directoryContext` содержит исходный выбранный каталог,
обнаруженные по `.project` + `src/` + `DT-INF/PROJECT.PMF` проекты EDT,
имена, версии платформы, наличие `.settings/`, настройки порта ближайшего
workspace и локальные Git root/branch/commit/detached HEAD. SessionStart передаёт
те же сведения как данные; форма показывает их в «О выбранном каталоге».
Git optional: отсутствие команды или недоступный репозиторий не блокируют профиль.
Сведения не включаются в переносимый экспорт. Явные подключения сохраняют
приоритет; только при их отсутствии `connectionSources.edt=edt_workspace`
обозначает URL, выведенный из prefs. Изменение порта инвалидирует preview,
а очередное обращение EDT-реле обновляет binding. Файл prefs не доказывает
запуск сервера: `liveVerified=false`. Отсутствующий файл не даёт default URL;
порт `8765` применяется только к существующему файлу без `mcpServerPort`.

При отсутствии профиля выше по дереву выполняется поиск `**/.ai/project.yaml`
под выбранным каталогом. Единственный результат определяет корень профиля;
несколько результатов требуют выбора конкретной папки. Ссылки/junctions,
`.git`, `.metadata`, `.settings`, `.ai`, `node_modules`, `vendor`, `.work`,
`.build` не обходятся; `.ai/project.yaml` проверяется непосредственно в каждом
каталоге. После 20 000 каталогов поиск останавливается с ошибкой, чтобы частичный
результат не выдавался за однозначный. Старый глобальный EDT URL не наследует
владение вложенным профилем только из-за его обнаружения.
Уже подключённые MCP-реле могут реагировать на изменение профиля/token по своему
обычному lifecycle, включая запуск managed runtime при настроенном mapping.

SessionStart выполняет только discovery профиля выбранного cwd/явного root и
передаёт краткое состояние в контекст. Существующие MCP-реле автоматически
обнаруживают профиль и без hook, а появление/изменение профиля обновляет их tools.
После create/load/import возвращается `sessionGuidance`: если host не обновил
инструменты в текущем чате, пользователь открывает новый чат в той же папке
или перезапускает Codex. Новый чат автоматически не создаётся.

Иконка включена в `logo` и `composerIcon`; MCP serverInfo и локальные tools
получают SVG icons, строки сервисов — встроенные в UI пиктограммы. Отображение
MCP icons зависит от host. Обе формы manifest содержат разработчика ShadobaAI.
Контракты сверены с [описанием плагинов](https://developers.openai.com/plugins/build/plugins),
[полями иконок](https://developers.openai.com/plugins/deploy/submission) и
[SessionStart](https://learn.chatgpt.com/docs/hooks). Hook требует доверия к текущему
определению в host; плагин не меняет настройки доверия.

## Выбор проекта и владение значениями

Назначенный `EDT_AI_PROJECT_ROOT` или однозначные MCP roots закрепляют папку.
Если host не предоставляет roots, используется рабочий каталог запуска MCP,
даже до создания `.ai/project.yaml`; каталог установки плагина исключён.
Явный пустой список roots снимает выбор, а неоднозначный блокирует запись.
В Windows рядом с полем доступна кнопка «Открыть папку» для Проводника;
при незакреплённом каталоге — «Выбрать папку» с системным диалогом выбора.
Отмена диалога сохраняет текущий ввод. Выбор папки запускается как операция
`pick_directory` с немедленным возвратом ID. `settings.read.operation` и
«Состояние» показывают незакрытый диалог; повторно открытый экран продолжает
ожидать его закрытия. Пока операция выполняется, изменение настроек и подготовка
заблокированы. После завершения данные обновляются автоматически. «Состояние»
запрашивает последнюю операцию сессии, а для завершённых load/create/update/apply
обновляет профиль и подключения без повторного запуска действий.
Диалог работает через поставляемый
Node-модуль Koffi, без PowerShell и дополнительных программ.
Если каталог не определён, начальный экран доступен, папку можно выбрать вручную для
текущей сессии настроек. Неоднозначные/некорректные roots оставляют доступными
экран и состояние операции, но блокируют запись. Сохранённый `active_project`
другой сессии не становится выбранной папкой native settings.

Выбирается ближайший профиль с сохранением Git-границ. До создания профиля
подкаталог Git относится к корню своего репозитория; вне Git используется
выбранный каталог. Это сохраняет instance key после инициализации профиля.
Ручной выбор папки не переключает другие MCP-сессии: для работы с её инструментами
пользователь открывает эту папку проекта в Codex.

URL всегда записываются в Codex instance override выбранной папки, включая
состояние без `.ai/project.yaml`. Без папки записывать URL нельзя. Они не
становятся общими defaults. `EDT_AI_INSTANCE` различает экземпляры одного
каталога; имя по умолчанию — `default`, автоматического уникального имени для
каждого окна нет. Для независимых экземпляров нужно явно задать разные имена.

Приоритет: process environment, `EDT_AI_CONNECTIONS_FILE`, Codex instance,
repo-local instance, project.local, tracked profile, допустимый legacy fallback.
Read возвращает `connectionSources`; поля, управляемые environment или явным
connections file, показываются read-only. Пустой native URL явно отключает
подключение, но environment сохраняет высший приоритет. Это не удаление override
и не возврат к profile default.

## Импорт и экспорт

Новый экспорт содержит managed/optional settings и tracked профиль. Выбор папки,
legacy общие URL, local/instance overrides и environment не экспортируются.
В другом окружении папка назначения выбирается заново. Native settings сохраняет
legacy CLI defaults как есть, не меняя их владельца при выборе другой папки.

Формат старого settings bundle версии 1 принимается: непустые URL из
`settings.mcp.required` записываются только в выбранный instance override.
Пустой legacy URL означает отсутствие fallback и не отключает URL из профиля.
Tracked `profile.connections` остаются defaults; existing local overrides и
environment имеют более высокий приоритет. Preview показывает effective URL,
наличие записи instance connections и изменения общих runtime-параметров,
включая Java/Node программы запуска. Общие параметры влияют на все проекты
с этим settings-файлом; instance URL — только на свой каталог и экземпляр.

Preview revision связывает payload, target, settings и файлы instance overrides.
Apply перечитывает входы под settings lock и повторно проверяет revision.
Каждый файл заменяется атомарно; при перехваченной ошибке выполняется rollback.
Это **не транзакция между файлами** и не гарантия восстановления после аварийного
завершения процесса/питания. После неизвестного исхода проверяется состояние
профиля, settings и overrides, а не выполняется автоматический повтор.

## Подготовка и состояние операции

`settings.run_check` начинает одну операцию и сразу возвращает `id/status`.
`settings.operation {operationId}` читает её состояние и итог без нового запуска.
Update/apply возвращают свой фактический результат синхронно и также видны через
`settings.operation`. Пока операция выполняется, повторная mutation/preparation
в этой MCP-сессии отклоняется. Read/preview не подменяют эту операцию.

Состояния: `running`, `completed`, `failed`, `outcome_unknown`; до первой
операции — `idle`. При аварийном завершении backend без корректного ответа
исход обозначается неизвестным. Истечение transport timeout не означает отмену.
Принудительного убийства bootstrap через четыре минуты и предложения повторить
нет. Polling ждёт завершения одной операции; после ответа `indexing/preparing`
новая полная подготовка возможна по кнопке, а не автоматически каждые пять секунд.

Результат содержит исходные папку и instance, даже если roots уже сменились.
История последних 16 операций хранится в памяти этой MCP-сессии. Она не
восстанавливается после перезапуска host. Номер отсутствующей операции не
разрешает повтор: сначала проверяются фактические settings/runtime. У зависшего
backend нет общей кнопки force-cancel; его внутренние операции имеют собственные
timeouts. Безопасная отмена требует отдельного контракта по фазам операции.

Проверки имеют конкретные границы:

| Компонент | Что подтверждает успешная проверка |
| --- | --- |
| code-index | MCP discovery и health заявленных путей/freshness |
| BSL LS | MCP discovery и наличие native workspace API; workspace ещё не зарегистрирован и файл не анализировался |
| policy | Synthetic protocol probes, включая отрицательный ledger; исходник и нормы не проверялись |
| EDT/v8std | Только наличие URL; live-проверка этим экраном не выполняется |

`fullReadiness: not_verified` сохраняется. Подготовка может скачивать runtime,
запускать project daemon и временные процессы проверки. Она не является read-only
проверкой полного проекта или нормативным заключением. Зарезервированные поля
OpenViking не включают подключение/поиск; переключатель убран из native layout.

## Проверка реализации

Компоненты включаются независимо во вкладке «Сервисы» для папки/instance.
BSL LS по умолчанию отключён. Первоначальная подготовка сохраняет разрешение
штатных managed-стартов в этом scope; чтение/создание/загрузка профиля не готовят
runtime. Отключённый компонент пропускается без установки и запуска.

`settings.updates` и кнопки обновления используют один backend: `check` проверяет
стабильные upstream releases, `download` сохраняет кандидат, `apply` проверяет API
и применяет, `rollback` проверяет и возвращает предыдущий артефакт. Операции
наблюдаются через `settings.operation`, повтор для ожидания не нужен. Скачивание
не меняет active. Для code-index новые читатели блокируются на время переключения;
активные операции сначала должны закончиться. Ошибка остановки/восстановления
сохраняет maintenance-состояние и требует проверки фактического daemon.

В расширенном редакторе managed-компоненты поддерживают `enabled` и
`mode: auto|external` с `url`. Подключения EDT/v8std в профиле и managed external
поддерживают `headers_env` (header → имя переменной окружения), `timeout_seconds`,
`max_response_bytes`. Значения credentials не записываются и не экспортируются.
Дефолтный транспортный бюджет 32 МиБ защищает память; это не лимит ответа модели.

Для прежнего состояния с подтверждённым владельцем сохраняется существующий
каталог, включая живой daemon. Если владелец неизвестен, старые файлы сохраняются;
форма предлагает проверить и явно перенести только подключения в новый scope.
Без этого старые подключения не подставляются автоматически.

Реальные stdio fixtures проверяют изоляцию до/после init, пустые roots, Git-границы,
import/export roundtrip, приоритет environment, сохранение legacy CLI defaults,
одну долгую операцию и неизвестный исход. UI harness исполняет код MCP App:
polling не перезапускает подготовку, поле закреплённого проекта read-only,
поздний preview не применяется к изменённому вводу.

Нативная карточка установленного Codex и выполнение в ИБ этим набором fixtures
не принимались. Адресные live-проверки EDT, v8std и code-index, а также выявленное
ограничение BSL JAR описаны в [журнале](VERIFICATION.md) и
[повторном ревью в репозитории](https://github.com/ShadobaAI/edt-ai-core/blob/main/docs/reviews/2026-10-21-production-followup.md).

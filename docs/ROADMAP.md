# План развития

Статус ниже относится к реализации в исходниках, а не к результату проверки
конкретного установленного окружения. Функции интеграций описаны
в [INTEGRATIONS.md](INTEGRATIONS.md).

| Направление | Статус | Результат |
| --- | --- | --- |
| Профили и instance bindings | Реализовано | Переносимый профиль, локальные overrides, изоляция MCP-сессий |
| Настройки и диагностика | Реализовано | Общая/проектная форма, preview/apply, локальные экспорты, readiness |
| Managed code-index и BSL LS | Реализовано | Releases, integrity, подготовка, проверка, кандидат/откат |
| База знаний OpenViking | Режимы, workflow gates, клиентский адаптер и проверка подписанной публикации реализованы локально | Readiness, реальная публикация, серверные права и live-приёмка |
| MCP информационной базы | Планируется | Ограниченный read-only доступ к служебным фактам назначенной ИБ |
| Live-приёмка интеграций | Требует отдельной проверки | Наблюдаемые результаты на реальных серверах и проектах |

## OpenViking

Режимы `disabled`/`transitional`/`kora`, выбор коллекций, обязательность и
ограничения workflow и клиентский поиск/чтение реализованы. Оставшиеся этапы интеграции:

1. Использовать реализованные схемы карточки и Git-manifest; определить внешнего
   владельца review и публикации.
2. Подготовить минимальные проверенные коллекции БСП и проекта.
3. Подтвердить серверные границы read-only доступа для реализованного адаптера;
   фильтрация клиентских инструментов сама по себе не подтверждает права.
4. Связать Git-ревизию с индексом, включая изменения и удаления карточек.
5. Добавить effective-настройки, поиск, readiness и целевые gates
   в схемы, UI, runtime, навыки и диагностику как согласованный контракт.
6. Проверить реальные сценарии переиспользования, неверную версию карточки,
   недоступность, устаревший индекс, попытку записи и выход за разрешённую область.

Готовность означает работающий поиск, подтверждённую редакцию и технически
ограниченное чтение. Наличие URL или успешный `tools/list` этого не доказывают.

## MCP ИБ

1. Утвердить перечень разрешённых служебных сведений и формат ответа
   с идентичностью контура, временем и версией конфигурации.
2. Реализовать сервер с минимальными правами без произвольных запросов,
   выполнения кода, прикладных данных и операций записи.
3. Добавить отдельную привязку проекта/экземпляра, настройки и readiness.
4. Проверить расхождение версии ИБ и ветки, отказ доступа, изоляцию контуров
   и неизменность данных при запросах. Повторить проверки после обновления API.

Готовность MCP ИБ независима от OpenViking и разработки исходников.
Его отсутствие ограничивает задачи, которым необходимы именно факты ИБ.

## Приёмка плагина

Для выпуска фиксируются версия пакета, версии реально запущенных компонентов,
область проекта и наблюдаемые результаты: установка из магазина, открытие
обоих входов настроек, привязка нескольких чатов, фокусное изменение EDT,
нормативная проверка, диагностика BSL LS и тестовые сценарии включённых раннеров.
Неизвестный исход мутации, неверный endpoint и попытки выхода за source boundary
проверяются как отрицательные сценарии.

Миграция навыков из исходных окружений сверяется отдельно по
`skills/catalog.yaml`. Исключённые HelpSearchServer/SSL-MCP и отложенные
проектные профили не возвращаются ради формального совпадения с источниками.

# EDT editing contracts

Читай только раздел для текущего артефакта. Параметры и возможности сверяй с
живыми schema и `get_tool_guide` назначенного EDT. Примеры ниже не устанавливают
поддержку конкретного режима во всех версиях. Baseline, guards, обработка job и
проверки результата определены в родительском навыке.

## BSL

- Для метода предпочитай `read_method_source`. Возвращённый `contentHash` может
  относиться ко всему модулю: передавай непреобразованный token в предусмотренный
  контрактом `expectedHash`, не вычисляй его из текста метода. После изменения
  прежний token не переиспользуется.
- При поддержке method modes выбирай `replaceMethod` для замены одного метода,
  `insertBefore`/`insertAfter` для вставки рядом с установленным `methodName`,
  `searchReplace` для уникального фрагмента. Сохраняй обязательные anchor и hash
  guards. Для замены метода учитывай входящие в заменяемый span документацию и
  аннотации; сохраняй имя, вид процедуры/функции и нужные директивы. Вставка не
  должна разрывать блок аннотаций/документации соседнего метода.
- Неоднозначный anchor, stale hash, syntax error или неподдержанная декларация
  требуют разрешения конкретной причины. Не переходи к whole-module rewrite,
  `overwrite=true` или `skipSyntaxCheck=true` как обходу отказа.
- Выбирай один способ адресации модуля по guide: `modulePath` либо `objectName`
  с нужными selectors. Создание файла модуля не доказывает adoption метаданных
  расширения. Block-balance/syntax check записи не заменяет EDT diagnostics.

## Запросы и DCS

- Проверяй полный изменённый запрос через `validate_query` в owning `projectName`;
  для запроса СКД используй поддержанный `dcsMode`. Проверяй `valid`, а не только
  успешность вызова. Статическая проверка не доказывает строки, итоги, права или
  производительность.
- Для DCS, вариантов, динамических списков и conditional appearance начни с
  `dcs get` точного root, затем читай только нужные возвращённые nodes/pointers.
  Summary root не является полным запросом или всеми настройками. Неизвестный
  writable vocabulary уточняй через поддержанный `options`/guide.
- Сохраняй возвращённый `hash` и передавай `expectedHash` согласно контракту;
  `replace`, `remove` и index-addressed изменения требуют hash guard. Копируй
  реальные pointers, не угадывай индексы; после записи обнови адреса и guards.
- Для существующего узла предпочитай `update`, для намеренного создания —
  `upsert`. `replace` может сбросить пропущенные значения и коллекции: весь
  replacement должен входить в scope. `remove` требует области удаления.
- Поддержку typed chart и других конструкций устанавливай по текущему guide;
  не переноси ограничения старой версии как универсальный запрет. Недоступный
  режим не разрешает generic metadata или файловую запись вместо DCS.
- Для разрешённого whole-schema XML transfer прочитай все `nextOffset` pages
  при неизменном hash и передай один полный документ с destination hash по guide.
  Не отправляй отдельную страницу или смесь XML и structured members.
- Проверь затронутые nodes, сохранность настроек и окончательный запрос, когда
  он изменён. Это дополняет обязательную focused EDT post-validation.

## Метаданные и формы

Читай `get_metadata_details` минимального owning node; `full=true` нужен только
для реальных членов коллекции. Установи programmatic name до записи: synonym
search не делает синоним допустимым write identifier. Для rename/delete оцени
затронутые данные, ссылки, права и интеграции; не расширяй операцию каскадом без
соответствующего scope.

Для command interface сначала установи точный адрес, после изменения проверь
сохранённые visibility, role overrides и порядок. Не меняй serialized files.
Не найденный role-rights target не является разрешением удалить права.
`resync_to_disk` пишет MODEL -> DISK даже без cleanup flags: это самостоятельный
эффект, а не read-only диагностика. Очистка orphan rights требует отдельной
области удаления и доказательства отсутствия target; неопределённые targets
сохраняй. Не включай полный export, overwrite или revalidation вне scope.

При визуальной приёмке формы используй snapshot/screenshot вместе с model
diagnostics. Пустое изображение не доказывает пустую форму. Startup render flags
и requested/forced state не доказывают существование буфера: проверь фактический
outcome renderer до вывода о дефекте или изменения настроек.

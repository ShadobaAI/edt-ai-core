# Поведенческие smoke-сценарии навыков

Это задачи выбора действий по bundled skills, а не тест совпадения слов в skills
и не модель реального EDT/OpenViking. Все факты задач синтетические.

Наборы сценариев:

- `kora-inputs.json` и `kora-rubric.json` — маршруты, достаточность решения,
  разрешения и результаты операций.
- `diagnostics-inputs.json` и `diagnostics-rubric.json` — оценка диагностик,
  соразмерность исправлений и проверок, исходная база задачи и приёмка.

1. Выбрать затронутый набор или ID. Новый исполнитель без истории разработки
   читает только выбранные inputs и нужные текущие навыки. Для KORA это
   `skills/1c-routing/SKILL.md`, `skills/1c-code-index/SKILL.md`,
   `skills/1c-code-change/SKILL.md` и нужные references. Для диагностик —
   `skills/1c-code-change/SKILL.md`, `skills/bsl-ls-mcp/SKILL.md`, общий
   `skills/1c-routing/references/diagnostics.md`, английские критерии
   `skills/1c-code-change/references/quality.md` и специализированный навык по сценарию.
   Не показывать исполнителю rubric или ожидаемый вывод.
2. Исполнитель отвечает по каждому ID: решение, необходимые следующие действия,
   существенные ограничения. Никаких изменений или внешних вызовов.
3. Отдельный reviewer сопоставляет ответы с rubric выбранного набора и инструкциями.
   Оценивать смысл и реальные решения, а не совпадение формулировок.
   Проверять как обоснованное исправление, так и решение сохранить достаточный
   простой код; количество исправленных предупреждений не является мерой успеха.
4. При провале исправить инструкции/сценарий и повторить затронутые задачи новым
   исполнителем.

Результат отдельного прогона не гарантирует поведение другой модели или хоста и не заменяет независимый пилот и live-приёмку. Runner Node не объявляет эти сценарии автоматическими CI-тестами.

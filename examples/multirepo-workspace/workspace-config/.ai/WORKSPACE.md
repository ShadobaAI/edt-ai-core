# Правила демонстрационного продукта

База поставщика находится в repository base. Собственные изменения размещаются
в product; временные исправления — в patch. В этом примере base и framework
доступны только для чтения. Само наличие зависимости не расширяет Write set.

YaXUnit-тесты принадлежат unit-tests, framework — отдельному upstream repository.
Сценарии Vanessa принадлежат ui-tests. Для каждого запуска выбирается assembly
и отдельная тестовая среда; authoring не разрешает запуск ИБ автоматически.

Имена EDT-проектов в декларации являются примером. Их соответствие checkout,
версии платформы и фактический состав ИБ проверяются до зависимой операции.
Проекции unit-base/unit-product/unit-patch читаются как состояние test-контура,
не становятся владельцами записи канонического кода.

Для патча Read set включает base/product/framework, Write set — patch и только
явно выбранные тестовые repositories. Release связывает manifest и test receipts
с SHA-256 проверенного CFE. Установка в прикладную ИБ — отдельный эффект.

Нормы, правила именования и сопровождения поставки уточняются для реального
продукта. Этот пример не переносит префиксы CRM или Kafka в общее ядро.
